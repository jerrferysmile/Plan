# 前途 QIANTU — INTJ 行动框架

一个**私人、本地、能触发决策**的行动框架工具，把「季度复盘、年度目标、底线、赛道观察」四件事做成可执行的结构，而不是又一个待办清单。

- 纯静态网页，**双击即用**，无需安装、无需联网、无账号。
- 数据只存在这台电脑的浏览器里，支持 JSON 手动备份与迁移。
- 界面为深色、克制风格：结论先行、数字优先、少而硬。

---

## 快速开始

1. 双击 `app/index.html`（或双击根目录的 `打开前途.bat`），用 Edge / Chrome 打开。
2. 第一次打开是空白数据：先去「年度目标」立项 1–2 个目标，再开始本季复盘。
3. 每季度首周做一次复盘；每季度结束后在「设置与备份」导出一次 JSON。
4. 想看完整效果：在地址栏的 `index.html` 后加 `?demo=1`（如 `app/index.html?demo=1`），进入演示数据模式，**不会保存**任何修改。

> 注意：请用浏览器直接打开文件。聊天窗口、文件管理器里的「预览」不执行脚本，页面会表现为不能操作（只显示静态界面）。如果打开后一直空白、或看到提示「应用没有正常启动」，说明脚本没跑起来——请改用 Edge/Chrome 打开本地文件。

> 名字为什么叫「前途」：它只回答一个问题——按现在的路径走下去，三年后的处境是否成立。工具不煽情、不许愿。

## 功能地图

| 模块 | 做什么 | 关键约束 |
|---|---|---|
| 总览（首页） | 当前季度状态、年度目标下一步、底线状态、本周信息定投、待处理提醒 | 只显示「接下来要判断的事」，不铺满数据 |
| 季度复盘 | 四本账：主业收益 / 技能积累 / 存款负债 / 风险，自动算有效时薪、储蓄率、安全垫；结论必填 | 结论区不写完不能提交 |
| 年度目标 | 每年最多 2 个核心目标，写「完成标准、关键结果、反目标、预算」 | 新增第 3 个必须先归档一个；7 月年中校准；年末结项打分 |
| 底线 | 三条默认规则（长期无成长 / 身体透支 / 薪资低于市场），季度复盘后自动判定绿黄红 | 转红必须填「决策卡」：设期限观望 / 启动准备 / 执行退出 |
| 赛道雷达 | 观察条目的信号、能力交集、拥挤度、研究触发条件、回看日期 | 观察中必须满 30 天才可升级为「研究中 / 已进入」（主动放弃不受限） |
| 设置与备份 | 市场中位数、信息定投目标、JSON 导出/导入、清空 | 导入会覆盖，操作前先导出 |

### 自动计算规则

- 有效时薪 =（主业 + 副业 + 其他月收入）÷ 月均总工时（含通勤/加班）
- 储蓄率 =（月总收入 − 月均总支出）÷ 月总收入
- 安全垫 = 现金存款 ÷ 月均总支出（用总支出，偏保守）
- 薪资底线：**市场有效时薪 = 市场月薪中位数 ÷ 174h**；有效时薪连续 2 季低于市场有效时薪的 80% 即触发
- 无成长：连续 2 季「原地踏步 / 在消耗」且当季技能投入低于阈值
- 身体透支：连续 2 季周均熬夜 ≥ 4 天 或 体检新增异常 ≥ 2 项

阈值都可以在「底线」页直接改，改完立即按已有复盘重算。

## 数据与备份

- 存储：本机浏览器 `localStorage`，键名 `qiantu:v1`。
- 备份：设置 → 导出 JSON，文件名形如 `前途备份-2026-10-29.json`。
- 迁移：在新电脑/新浏览器打开同一份 `app/index.html`，设置 → 导入备份。
- 提醒：超过 90 天未导出，首页会出现备份提醒；每季度复盘后顺手导出最省事。
- 演示模式（`?demo=1`）不写入任何数据。

> 历史数据兼容：旧版（原名「校准」，键名 `calibrate:v1`）的本地数据在首次打开新版时会自动迁移到新键；旧版导出的 JSON 备份也可以直接导入。

> 注意：清理浏览器缓存/「清除站点数据」会删除 localStorage，务必保留 JSON 备份。

## 打包与分发

**三种用法，按需要选：**

| 方式 | 文件 | 适用场景 |
|---|---|---|
| 文件夹版（开发版） | `app/index.html` | 长期使用，四个文件放一起；改代码最方便 |
| 单文件版 | `dist/前途.html`（约 156 KB） | 拷到 U 盘、网盘、发给自己；一个文件双击即用 |
| 本地包 zip | `dist/前途-v1.0-本地包.zip`（约 55 KB） | 归档备份 / 换电脑迁移（含说明与方案文档） |

**重新生成打包产物**（改完代码后）：

```powershell
node build.js
```

脚本会把 `app.css`、`core.js`、`views.js` 内联进一个 HTML，并自动校验：外链必须清空、`$$` 工具函数与启动函数必须完整（防止替换时被 `$` 转义破坏）。产物在 `dist/` 下。

**注意事项**

- 单文件版与文件夹版共用同一份浏览器 localStorage（同一 `file://` 来源），可以放心切换，不会出现两套数据。
- 数据**不会跟着文件走**：把 `前途.html` 拷到另一台电脑后，需要先在旧环境「设置 → 导出 JSON」，再到新环境导入。
- 没有做 Electron / Tauri 安装包：MVP 不需要系统权限和后台能力，单文件已满足「本地、离线、双击即用」。以后如果要系统通知、开机自启或自动写文件备份，再评估用 Tauri 打包成桌面应用。

## 开发与测试

需要 Node（任意较新版本；仓库测试使用 Node 24，无第三方依赖）：

```powershell
node build.js             # 生成 dist/前途.html 单文件版
node tests/core.test.js   # 46 项逻辑测试
node tests/e2e.test.js    # 18 项浏览器端到端测试（需要 Edge，脚本用 CDP 驱动无头浏览器）

# 也可以对单文件版跑同一套 E2E，确认打包产物没坏：
node tests/e2e.test.js "file:///D:/intj复盘软件/dist/前途.html"
```

E2E 会启动一个临时 Edge 实例（随机端口 9333，独立临时 profile），跑完自动清理。

## 已知限制（MVP 有意为之）

- 单机单用户：不做云同步、多设备；用 JSON 迁移。
- 不自动弹通知：复盘是低频高密度动作，靠首页提醒 + 自己的日历。
- 无图表：历史对比用表格展示关键数字（图表在 v0.2）。
- 季度按自然季度（1/4/7/10 月）；方案里预留了 `quarterStartMonth`，但 MVP 界面未开放修改。
- 复盘编辑会自动保存（约 0.6 秒防抖），离开页面时也会落盘。

## 为什么这样设计（对应原始设想）

1. **每季度复盘**：四本账固定字段 + 强制结论 → 避免「凭感觉复盘」。
2. **每年只定 1–2 个核心目标**：硬上限 + 放弃清单 → 防止计划堆积、精力分散。
3. **设置底线**：规则化、可量化、触发即决策 → 在沉没成本里也能理性退出。
4. **持续收集信息、等增量赛道**：观察清单 + 30 天冷静期 + 研究触发条件 → 用条件判断替代 FOMO。

## 常见问题

**Q：换电脑怎么办？**
导出 JSON → 拷走整个文件夹 → 新电脑打开 `app/index.html` → 导入 JSON。

**Q：数据会不会上传？**
不会。没有任何网络请求，代码可自行检查（无 fetch/XHR）。

**Q：为什么观察期是 30 天？**
强制把「看到就想冲」变成「看到 → 记录信号 → 设定触发条件 → 到期再判断」。放弃和删除不受限制，避免把自己锁死。

**Q：复盘能补录吗？**
可以，最近 6 个季度内都能新建复盘；同一季度只能有一份记录，草稿会出现在复盘列表里。

**Q：想恢复空白状态？**
设置 → 清空所有数据（会二次确认，请先导出备份）。
