## 1. 产品定位

### 1.1 它解决什么

INTJ 的问题通常不是「不会规划」，而是：

- 计划越堆越多，**执行与复盘脱节**，年底发现方向没错但没留下证据；
- 目标没有**退出条件**，在沉没成本里耗着；
- 信息一直在看，但**没有沉淀成判断**，等到赛道挤满了才发现；
- 复盘靠感觉，**不量化**，年年写同样的反思。

这个软件只做三件事：

1. **收口**：每个季度用固定字段强制过一遍四本账（收益/技能/存款/风险），不给「凭感觉」留空间。
2. **限量**：一年只允许 1–2 个核心目标，写入即锁定，多出来的必须先进「放弃清单」。
3. **触发**：底线条件与赛道信号是**可配置的规则**，达到阈值就进入决策流程，而不是继续「再观察观察」。

### 1.2 它明确不做什么（反需求）

| 不做 | 原因 |
|---|---|
| 社交、分享、排行榜 | 与私人复盘无关，还引入比较焦虑 |
| 积分、徽章、连续打卡 | 用游戏化掩盖判断，INTJ 不吃这套 |
| 复杂甘特图、项目排期 | 这是年度框架，不是项目管理工具 |
| AI 情绪安抚、鸡汤文案 | 只需要事实和选项 |
| 每日强提醒 | 复盘是季度/年度动作，天天弹窗只会被静音 |
| 云同步、多端 | MVP 用 JSON 导出导入代替，避免隐私和复杂度 |

### 1.3 设计原则

1. **结论先行**：每个模块的最后一步必须是一句「所以我的决定是……」，没有结论的复盘不算完成。
2. **数字优先，量表辅助**：能量化就量化；不能量化的用 1–5 级量表，不用形容词。
3. **少而硬**：字段宁少勿多，但每个字段都要能支撑一个决定。
4. **强制留白**：首页只显示「接下来 90 天要判断的 3 件事」，不铺满数据。
5. **可回溯**：所有记录只追加不覆盖，历史对比是一等公民。

## 2. 目标用户与使用节奏

### 2.1 用户画像

- 一个人，25–40 岁，上班为主业，可能在做副业或准备转型；
- 习惯用结构化方式思考，讨厌模糊的「加油」「坚持」；
- 数据敏感，愿意为「记录」付出 30–60 分钟/季度的成本；
- 设备：Windows 电脑为主，浏览器打开本地文件。

### 2.2 使用节奏（核心设计约束）

| 频率 | 动作 | 耗时 |
|---|---|---|
| 每周（可选） | 记 1 条赛道观察 / 1 次轻量状态记录 | 5–10 分钟 |
| 每季度首周 | **季度复盘**（四本账 + 结论 + 下季 Top1） | 45–60 分钟 |
| 每年 1 月 | 立项：设定 1–2 个年度目标 + 底线规则 | 30 分钟 |
| 每年 7 月 | 年中校准：目标是否还成立 | 20 分钟 |
| 每年 12 月 | 结项：目标评分、归档、生成年度快照 | 30 分钟 |

> 节奏是产品的一部分：**低频、高密度**，拒绝把复盘做成日常打卡。

## 3. 名字与调性

- 产品名：**「前途」**（QIANTU）——它只回答一个问题：按现在的路径走下去，三年后的处境是否成立。工具不煽情、不许愿。
- 备选：「复盘台」「基线」「北极星」。
- 界面调性：冷色、克制、高信息密度但排版留白；无插画、无渐变炫技；重点用「状态色 + 数字」表达。

## 5. 核心模块设计

### 5.1 总览（首页）

只回答三个问题，各占一块：

1. **本季度还剩几天？季度复盘做了吗？**（未做 → 醒目提示 + 一键开始）
2. **年度目标现在到哪了？**（最多 2 条，各一行：目标名 / 进度状态 / 下一步动作）
3. **有没有东西在悄悄变红？**（底线状态、赛道雷达里「研究中」的条目数）

顶部一行「本季一句话判断」（从上一次复盘结论带出，可编辑）。

### 5.2 季度复盘（四本账）

**流程**：开新复盘 → 带出上季设定值 → 逐项录入 → 系统算偏差 → 写结论 → 落库 → 更新首页。

**通用结构**：每个维度 = 季初目标值 + 季末实际值 + 自动偏差 + 根因 + 下季动作。

#### ① 主业收益

| 字段 | 类型 | 说明 |
|---|---|---|
| 月均总收入 | 数字 | 本季三个月平均 |
| 收入结构 | 三个数字 | 主业 / 副业 / 其他（自动算占比） |
| 有效时薪 | 自动 | 总收入 ÷（工作小时 + 通勤 + 加班） |
| 涨薪/跳槽节点 | 单选 | 无变化 / 已涨 / 在谈 / 已跳 / 计划中 |
| 市场对比 | 数字 | 手动录入同岗位市场中位数（季度更新一次即可） |
| 判断 | 单选 | 收益健康 / 结构待优化 / 需要换环境 |

#### ② 技能积累

| 字段 | 类型 | 说明 |
|---|---|---|
| 本季投入时长 | 数字 | 小时，估算即可 |
| 技能条目 | 列表 | 技能名 / 当前等级 1–5 / 证据（作品、证书、可展示成果）/ 是否继续 |
| 可迁移性 | 单选 | 高（跨行业可用）/ 中 / 低（绑定当前公司） |
| 判断 | 单选 | 有积累 / 原地踏步 / 在消耗 |

> 决策规则提示：投入时长 > 0 但**无证据**，自动标黄「练习未沉淀」。

#### ③ 存款与负债

| 字段 | 类型 | 说明 |
|---|---|---|
| 现金存款 | 数字 | 活期+货基等可动用部分 |
| 储蓄率 | 自动 | （收入−支出）÷ 收入 |
| 安全垫（runway） | 自动 | 存款 ÷ 月均必要开支，单位「月」 |
| 负债 | 列表 | 类型 / 余额 / 月供 / 利率 |
| 判断 | 单选 | 安全（≥12 个月）/ 警戒（6–12）/ 危险（<6） |

#### ④ 风险

| 字段 | 类型 | 说明 |
|---|---|---|
| 社保/公积金 | 状态 | 连续缴纳 / 断缴 / 未缴，附最近核对日期 |
| 身体健康 | 三项 | 体检异常项数 / 周均运动次数 / 周均熬夜天数 |
| 职业风险 | 单选 | 公司或行业收缩 / 岗位可替代性高 / 一般 / 低 |
| 合同与法律 | 自由文本 | 竞业、期权、欠薪、合同到期等 |
| 判断 | 单选 | 可控 / 需处理 / 已触发底线 |

**结论区（必填，未填不能提交）**：

- 本季一句话结论
- 三个选项：继续按计划 / 调整方向 / 启动退出评估（选「退出评估」→ 进入底线模块的决策卡）
- 下季度**唯一最重要的事**（Top 1，只能写一条）
- 本季放弃清单（做了什么但其实不该做的）

**历史对比**：复盘列表可按维度并排对比最近 4 个季度（如有效时薪、runway、技能等级曲线），用简单折线或表格，不追求炫酷。

### 5.3 年度核心目标

- **硬上限 1–2 个**：新增第 3 个时，弹窗强制要求先归档一个（「今年不做」）。
- 每个目标字段：

| 字段 | 说明 |
|---|---|
| 目标名 | 一句话 |
| 完成标准 | 必须可验证（有数字或可交付物），写不出就不算目标 |
| 关键结果 | 最多 3 条，每条带数字 |
| 截止时间 | 日期 |
| 反目标 | 为达成它明确不做什么（防跑偏） |
| 资源预算 | 时间/月 + 金钱 |
| 关联季度 | 目标拆到哪几个季度检查 |
| 状态 | 未开始 / 进行中 / 已达成 / 已放弃（含原因） |

- **年中校准**：7 月自动提示，对每个目标做一次三选一：继续 / 降级为「维持」/ 正式放弃（写原因）。
- **年末结项**：打分（0–100，自评）+ 一句话归因 + 归档，进入年度快照。

### 5.4 底线系统（本产品的差异点）

底线不是「提醒你别累着」，而是**预先写好退出条件与动作**，避免在情绪和沉没成本里做决定。

**默认三条规则（可编辑，但结构固定）**：

| 规则 | 默认判定条件 | 检查时点 |
|---|---|---|
| 长期无成长 | 连续 2 个季度「技能积累」判断为「原地踏步」或「在消耗」，且投入时长低于阈值 | 季度复盘时自动算 |
| 严重透支身体 | 连续 4 周周均加班 > 15h；或体检新增 ≥2 项异常；或周均熬夜 ≥4 天 | 季度复盘时手动确认 |
| 薪资长期低于市场 | 连续 2 个季度有效时薪低于市场中位数的 80% | 季度复盘时自动算 |

**状态机**：绿（未触达）→ 黄（接近阈值，预警）→ 红（触发）。

**红灯 = 进入决策模式**，必须完成一张「决策卡」：

1. 已触发的规则与证据（自动带出）；
2. 三个预设选项：**A 设定期限观望（≤60 天）** / **B 启动准备（更新简历、盘点技能、接触机会）** / **C 执行退出（定离职/转型时间表）**；
3. 选择 + 理由 + 执行截止日；
4. 下次复盘的检查点。

> 规则：红灯未完成决策卡时，首页持续置顶；决策卡一旦提交，状态转为「已决策」，并记录决策日期，避免反复摇摆。

### 5.5 赛道雷达

解决「持续收集信息、等增量赛道出现，而不是硬挤拥挤赛道」。

**观察条目字段**：

| 字段 | 说明 |
|---|---|
| 赛道/方向名 | 一句话 |
| 信号来源 | 文章、人、招聘数据、行业报告等（可贴 URL） |
| 看到了什么信号 | 支持它「增量」的事实，≥2 条 |
| 与我的能力交集 | 哪些技能可迁移，缺口是什么 |
| 拥挤度 | 1–5（越高越挤） |
| 我的判断 | 观察中 / 研究中 / 已放弃 / 已进入 |
| 进入研究的触发条件 | 例如「出现 3 个以上非巨头玩家的融资」「我的技能缺口补到能接单」 |
| 下次回看日期 | 默认 30 天后 |

**状态流转**：观察中 →（满足触发条件）研究中 →（验证后）已进入 / 已放弃。

**硬规则**：任何新赛道必须先在「观察中」停留满 30 天，才能改状态；防止 FOMO 驱动决策。

**信息定投**：设置页可设「每周信息输入时长目标（默认 60 分钟）」，首页显示本周是否完成，但不做打卡积分。

### 5.6 设置与数据

- 导出 JSON（全文备份）、导入 JSON（覆盖或合并二选一）；
- 只存本机 localStorage，不上传任何数据；
- 支持「重置」但要输入确认；
- 数据文件命名：`前途备份-YYYY-MM-DD.json`。

## 6. 关键流程

### 6.1 季度复盘流程

```
首页提醒「Q3 复盘未做」
  → 新建复盘（自动带出上季目标值与市场数据）
  → 四本账逐项录入（每步可暂存）
  → 系统计算偏差与自动判断（runway、有效时薪、底线规则）
  → 写结论：继续 / 调整 / 启动退出评估
  → 生成下季 Top1 + 放弃清单
  → 完成 → 更新首页 + 底线状态 + 历史对比可用
```

### 6.2 底线触发 → 决策

```
季度复盘算出规则触发
  → 状态转红 → 首页置顶「决策未完成」
  → 打开决策卡：证据 + 三选项
  → 选择并填截止日
  → 关灯条件：到期复查
```

### 6.3 年度循环

```
1 月立项（目标 ≤2 + 底线规则确认）
→ 4/7/10 月三个季度复盘（7 月含年中校准）
→ 12 月结项：打分、归因、归档、年度快照
```

### 底线决策卡

```
⚠ 已触发底线：薪资长期低于市场（连续 2 季 <80%）
```

## 9. 视觉与交互规范

- 深色为主（可用浅色主题），2 色强调：绿（健康）/ 橙（预警）/ 红（触发），加一个中性蓝作主色。
- 字体：系统字体；数字用等宽或表格数字（tabular），方便对齐比较。
- 不做动效炫技，只保留状态切换的短过渡。
- 所有「删除/重置」二次确认；所有录入自动暂存（防丢）。

## 10. MVP 范围与验收标准

### 10.1 MVP 必做

1. 首页总览（四块信息）
2. 季度复盘：四本账完整字段 + 自动计算（偏差、runway、有效时薪）+ 结论必填 + 历史列表
3. 年度目标：≤2 个硬限制 + 放弃清单 + 年中校准提示
4. 底线：三条默认规则 + 状态机 + 决策卡
5. 赛道雷达：条目 CRUD + 30 天观察规则 + 状态流转
6. 数据：localStorage 持久化 + JSON 导出/导入
7. 历史对比：最近 4 个季度关键数字并排查看

### 10.2 明确放到 v0.2+

- 图表可视化（折线/雷达图）
- 浏览器通知提醒
- 数据加密/密码
- 多设备同步
- 模板自定义（新增第五本账）

### 10.3 验收标准（自测清单）

- [ ] 断网、双击文件即可使用，无需安装
- [ ] 录入 4 个季度数据后，历史对比正确显示
- [ ] 输入第 3 个年度目标时被系统拦下，要求先归档

- [ ] 有效时薪低于市场中位数 80% 持续两季，薪资规则转红并生成决策卡
- [ ] 决策卡未提交时，首页持续提示
- [ ] 赛道条目 30 天内无法从「观察中」改为「已进入」
- [ ] 导出 JSON 后清空数据，再导入可完整恢复
- [ ] 刷新页面数据不丢
- [ ] 结论区为空时不能提交复盘

## 11. 技术方案

| 项 | 选择 | 理由 |
|---|---|---|
| 形态 | 单 HTML 文件（内嵌 CSS/JS） | 双击即用，零安装，无需服务器，方便备份 |
| 框架 | 原生 JS（可选轻量模板） | MVP 复杂度低，避免构建链和依赖衰减 |
| 存储 | localStorage（键名 `qiantu:v1`） | 单机单用户足够；数据量 < 5MB |
| 导出 | Blob 下载 JSON | 手动备份 |
| 目录 | `app/index.html` 单文件；`docs/` 放方案与迭代记录 | 结构清晰 |
| 兼容 | Edge / Chrome 最近两个版本 | Windows 环境 |

> 备选：若后续要做图表和更复杂交互，再迁移到 Vite + React，但**MVP 不引入构建工具**。

## 13. 风险与取舍

| 风险 | 应对 |
|---|---|
| 字段太多导致弃用 | MVP 已砍到 4 本账 × 5 类字段；先跑再说，弃用即砍 |
| localStorage 被清 | 强制每季度导出一次 JSON，首页提示「上次备份距今 N 天」 |
| 单文件代码膨胀难维护 | 预计 1500–2500 行；超过后拆模块或用模板字符串组织 |
| 规则过严产生抵触 | 底线规则阈值可编辑；红灯只要求「做决定」，不要求必须离职 |
| 变成又一个「规划了但不做」的工具 | 首页只显示「下一步动作」，不显示宏大计划 |

**实现时与本文档的三处有意偏差（更合理，已同步到 README）：**

1. **薪资底线换算**：文档写「有效时薪低于市场中位数 80%」，但月薪与小时工资不可直接比较。实现为 **市场有效时薪 = 市场月薪中位数 ÷ 174h**，再与有效时薪比较。
2. **安全垫（runway）**：文档写「存款 ÷ 月均必要开支」，实现改用 **月均总支出**，更保守；表单只收一个支出字段，减少录入负担。
3. **30 天观察规则**：**升级**为「研究中 / 已进入」受 30 天限制；**主动放弃 / 删除**不受限，避免把用户锁死在错误条目里。

**MVP 未包含（按计划留到 v0.2+）**：图表可视化、浏览器通知、多设备同步、自定义复盘模板、界面内修改季度起始月。
